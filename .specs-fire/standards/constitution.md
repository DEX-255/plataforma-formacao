# Project Constitution

> Políticas universais, válidas para todo o código do projeto.
> Sempre herdado da raiz — módulos não sobrescrevem.

## Fonte de verdade

**As regras de negócio deste projeto NÃO moram aqui.** Elas moram em
[`specs/02-dominio.md`](../../specs/02-dominio.md), numeradas de `RN-01` a `RN-18`.

Este arquivo cobre apenas o que a especificação não cobre: fluxo de git, revisão e
segredos. Havendo divergência entre este arquivo e `specs/`, **`specs/` vence** — e a
divergência é defeito a ser corrigido, não ambiguidade a ser interpretada.

## As regras invariantes

Todo código escrito neste projeto está sujeito às `RN-01`…`RN-18`. Elas valem em
qualquer tela, e são responsabilidade do banco e do servidor — nunca só da interface.

Quatro delas são de severidade máxima, porque a violação causa dano irreversível a uma
pessoa real:

| Regra | O que garante |
|---|---|
| `RN-03` | O participante nunca vê nota nem observação interna durante a formação |
| `RN-08` | Não existe vínculo armazenado entre mensagem anônima e autor |
| `RN-10` | Mensagens anônimas são exibidas em ordem aleatória fixa, sem horário |
| `RN-12` | Participante só enxerga a si mesmo |

Toda `RN` tem uma função em `dominio/regras.ts` e um teste correspondente. Ver
[`specs/07-qualidade.md`](../../specs/07-qualidade.md).

## Git

- **Commits**: convencionais (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`).
- **Referência à spec**: todo commit que implementa requisito cita o código no corpo
  (`RF-D1`, `RN-16`). É o que mantém spec e código amarrados depois que a memória desta
  conversa acabar.
- **Branch**: `main` sempre publicável. Trabalho em branch por work item.
- **Nada de `git init`, commit ou push sem pedido explícito.**

## Segurança

- **Nenhum segredo em código.** Variável de ambiente, sempre.
- **A `service_role` do Supabase nunca chega ao navegador** (`D-07`). Ela existe só em
  variável de servidor e é usada só pelo gerador do documento final.
- **A interface não conta como barreira.** Esconder um botão impede de clicar, não de
  pedir. Nenhuma decisão de acesso é tomada só em componente.
- Alteração que toca RLS, sessão ou o bloco interno do feedback exige revisão extra.
